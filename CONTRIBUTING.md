# Contributing to GC Stats Widgets

First of all, thank you for considering contributing to the GC Stats Widgets project! These widgets are the front of the GC Stats broadcast overlays (OBS Browser Source, embeds), and community involvement helps us cover more of the GC scene.

To maintain the quality and integrity of the project, please follow these guidelines.

## 🤖 AI Usage Policy

As explained in the organization's core principles, we don't accept raw AI work. AI is a tool, not a replacement for a developer.

- **AI Assistance is OK:** Using tools like Copilot, ChatGPT, or Claude to help you code is perfectly fine.
- **100% AI-Generated PRs are FORBIDDEN:** Submitting code entirely generated by AI without human oversight or understanding is strictly prohibited.

## 💡 How to Contribute

### 1. Start with a Discussion
Before you spend time writing code, **please open a "Feature Request" or "Bug Report" issue.**
- We do not guarantee that every contribution will be accepted.
- Opening an issue allows us to discuss the relevance of the feature and the implementation details to avoid wasted effort.

New widgets usually depend on a data endpoint exposed by [GC-Stats-Website](https://github.com/Osthelia/GC-Stats-Website), so mention in your issue whether that endpoint already exists.

### 2. Development Workflow
1. **Fork** the repository and create your branch from `main`.
2. Name your branch clearly: `feature/short-description` or `fix/short-description`.
3. Follow the installation steps in the `README.md` (`npm install`, copy `.env.example` to `.env`, `npm run dev`).

### 3. Code Standards
To keep the codebase clean and maintainable:
- **Type checking:** This is a Vite + React + TypeScript static front (no backend, no database). Before committing, run:
  ```bash
  npm run typecheck
  npm test
  ```
- **Adding a widget:** Create its folder in `src/widgets/` and register it in `src/widgets/registry.ts`. Keep each widget's dependencies lazy loaded so it only ships what it uses.
- **Styling:** Look and feel lives in `src/theme.css` and the per-widget `.css` files. Widgets must stay readable on a transparent background (OBS).
- **Translations:** Every user-facing text must be added to every supported locale in `src/i18n.ts`.
- **File headers:** Every `.ts` / `.tsx` file starts with the Osthelia header (description, copyright, license, link). Add it to new files and do not remove or alter it in existing ones (see [LICENSE.md](LICENSE.md)).

### 4. Submitting a Pull Request

   - Provide a clear description of what the PR changes or adds.
   - Reference the original Issue (e.g., Closes #123).
   - Ensure the project builds, type checks and tests pass (`npm run build` / `npm run typecheck` / `npm test`).
